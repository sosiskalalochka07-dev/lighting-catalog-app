# Отчет по лабораторной работе
## Тема: Разработка приложения для работы со справочником светильников

### 1. Постановка задачи
Необходимо разработать desktop-приложение с графическим интерфейсом для управления базой данных (справочником светильников). 

**Структура данных (Вариант 28):**
- Название светильника;
- Номинальная площадь освещения лампы;
- Стоимость;
- Площади аудиторий.

**Функциональные требования:**
1. Реализовать ввод, накопление, редактирование и удаление данных.
2. Обеспечить сохранение и загрузку данных в формате JSON.
3. Выполнить обработку данных согласно варианту:
   - Определить минимальную стоимость организации системы освещения.
   - Построить распределение аудиторий по стоимости организации системы освещения.
4. Визуализировать исходный набор данных и результаты обработки.
5. Реализовать поиск и навигацию по записям.

**Ограничение:** Использование библиотеки `pandas` запрещено.

### 2. Архитектура приложения
Приложение построено по паттерну **MVC (Model-View-Controller)**, реализованному в рамках одного файла:

- **Model (Данные и Логика):** Данные хранятся в памяти в виде списка словарей (`self.db`). Реализованы функции сериализации/десериализации JSON и математические вычисления (расчет количества светильников через `math.ceil`, подсчет итоговой стоимости, поиск минимума и сортировка).
- **View (Интерфейс):** Графический интерфейс построен на встроенной библиотеке `tkinter` и расширении `ttk`. Визуализация графиков реализована через `matplotlib`.
- **Controller (Связь):** Класс `LightingCatalogApp` выступает в роли контроллера, связывая события нажатия кнопок (View) с методами обработки данных (Model) и обновлением интерфейса.

### 3. Проектные решения frontend
Для пользовательского интерфейса приняты следующие решения:

- **Главное окно:** Разделено на три логические зоны с использованием менеджеров геометрии `pack` и `grid`.
  - *Верхняя панель:* Кнопки глобальных действий (Импорт/Экспорт JSON, Вычисления, Очистка).
  - *Центральная панель:* Компонент `ttk.Treeview` для отображения БД в табличном виде с полосой прокрутки.
  - *Нижняя панель:* `LabelFrame` с полями ввода (`ttk.Entry`) для добавления/редактирования, а также блок поиска и навигации.
- **Окно вычислений:** Результаты и графики открываются в дочернем окне (`tk.Toplevel`), чтобы не загромождать главный интерфейс.
  - *Текстовая область:* `tk.Text` для вывода текстовых результатов (минимальная стоимость, отсортированный список).
  - *Графическая область:* Встраивание `matplotlib` через `FigureCanvasTkAgg`. Построен столбчатый график (bar chart), наглядно демонстрирующий распределение аудиторий по возрастанию стоимости освещения.
- **Валидация:** При вводе данных используется конструкция `try-except` для предотвращения ввода текста вместо чисел.

### 4. Проектные решения backend
- **Хранение данных:** Поскольку использование `pandas` запрещено, "база данных" реализована как список Python-словарей. Каждая запись имеет уникальный `id`, который инкрементируется при добавлении. Это обеспечивает целостность данных при редактировании и удалении.
- **Формат JSON:** Данные сохраняются в человекочитаемом формате с отступами (`indent=4`) и поддержкой кириллицы (`ensure_ascii=False`).
- **Алгоритм обработки (Вариант 28):**
  1. *Расчет стоимости:* Для каждой записи вычисляется необходимое количество светильников по формуле `N = ceil(Площадь_аудитории / Номинальная_площадь_лампы)`. Итоговая стоимость = `N * Стоимость_светильника`. Обработаны граничные случаи (если номинальная площадь <= 0).
  2. *Минимальная стоимость:* Используется встроенная функция `min()` по списку вычисленных стоимостей.
  3. *Распределение:* Для визуализации и анализа записи сортируются по возрастанию итоговой стоимости (`sorted(..., key=lambda x: x['total_cost'])`), что позволяет увидеть "диапазон" цен и сгруппировать аудитории от самых дешевых в освещении к самым дорогим.
- **Поиск:** Реализован линейный поиск по подстроке (без учета регистра) в поле "Название светильника" с мгновенным обновлением `Treeview`.
